# Dataset/Source Allocation & Validation Harness Architecture (Module 22)

## 1. Overview & Core Principles

Original Module 22 implements a formal dataset allocation and scientific validation harness framework for the Aero Piston Engine Digital Twin.

```
+-----------------------------------------------------------------------+
|                            DATASET SOURCE                             |
|  (SIMULATED, REPLAY, LIVE, VALIDATION_GROUND_TRUTH)                   |
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|                           DATASET MANIFEST                            |
|  (Metadata: Dataset ID, Version, Source, Intended Use, Checksum)      |
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|                    ALLOCATION & SPLITTING RULES                       |
|  (Train/Val/Test Temporal Splitting, Scenario Grouping, No Leakage)   |
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|              QUALITY, SCHEMA & INTEGRITY AUDITORS                     |
|  (NaN/Inf check, Timestamp monotonicity, SHA-256 Checksum Verification)|
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|                  POST-INFERENCE VALIDATION HARNESS                    |
|  Telemetry -> Pipeline -> Predictions + Isolated Ground Truth         |
|  -> Benchmark Metrics (Regression, 9-Class Taxonomy, Anomaly, RUL)    |
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|                     STRUCTURED VALIDATION REPORT                      |
|  (ValidationRun & ValidationReport: PASS / FAIL / PARTIAL / N/A)      |
+-----------------------------------------------------------------------+
```

## 2. Source Taxonomy & Intended-Use Matrix

### Source Categories (`SourceType`)
- `SIMULATED`: Synthetic telemetry generated by Module 17 forward physics model.
- `REPLAY`: Recorded telemetry from flight log CSV playback adapters.
- `LIVE`: Live hardware sensor telemetry acquired by onboard edge nodes.
- `VALIDATION_GROUND_TRUTH`: Isolated reference ground truth labels for post-inference validation.

### Intended-Use Categories (`IntendedUse`)
- `DEVELOPMENT`: Internal model and feature engineering iterations.
- `TRAINING`: Supervised ML model training.
- `VALIDATION`: Hyperparameter tuning and model selection.
- `TEST`: Final benchmark evaluation.
- `REPLAY`: Scenario playback verification.
- `SCIENTIFIC_VALIDATION`: Scientific physics & diagnostic accuracy validation.
- `DEMONSTRATION`: Interactive UI and ground station demonstration runs.

### Allocation Rules Matrix
| Source Type | Permitted Intended Uses |
| :--- | :--- |
| `SIMULATED` | `DEVELOPMENT`, `TRAINING`, `VALIDATION`, `TEST`, `SCIENTIFIC_VALIDATION`, `DEMONSTRATION` |
| `REPLAY` | `REPLAY`, `VALIDATION`, `TEST`, `SCIENTIFIC_VALIDATION`, `DEMONSTRATION` |
| `LIVE` | `VALIDATION`, `DEMONSTRATION` |
| `VALIDATION_GROUND_TRUTH` | `VALIDATION`, `TEST`, `SCIENTIFIC_VALIDATION` |

## 3. Dataset Manifest Schema (`DatasetManifest`)

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `dataset_id` | `str` | Unique dataset identifier. |

## 4. Train / Validation / Test Splitting & Data Leakage Prevention

1. **Chronological Time-Series Splitting (`DatasetSplitter.split_by_time`)**:
   - Preserves temporal order by sorting records by timestamp.
   - Splits without random shuffling (e.g. 70% Train, 15% Validation, 15% Test) to prevent future data leakage.
2. **Scenario / Group Splitting (`DatasetSplitter.split_by_scenario`)**:
   - Assigns entire scenario runs / missions to partitions so correlated records from the same run do not leak across training and test sets.
3. **Leakage Detection (`LeakageDetector`)**:
   - `check_temporal_leakage`: Detects overlapping timestamp intervals between partitions.
   - `check_duplicate_leakage`: Identifies duplicate timestamp records across partitions.
   - `check_ground_truth_leakage`: Verifies raw telemetry input records contain zero embedded ground-truth objects (`SimulationGroundTruth`, `Wiebe` parameters).

---

## 5. Post-Inference Ground-Truth Isolation

- **Invariance Rule**: `SimulationGroundTruth` is an isolated reference key. It is **NEVER** inserted into `RawSignalRecord`, ML feature vectors, Digital Twin physics, or advisory inputs.
- **Validation Pipeline Order**:
  $$\text{Telemetry Input} \xrightarrow{\text{Pipeline}} \text{Predictions} \xrightarrow{+} \text{Isolated Ground Truth} \rightarrow \text{Validation Metrics}$$
- Post-inference comparison evaluates predictions against ground truth without exposing ground truth to the inference pipeline.

---

## 6. Validation Harness Metrics

- **Regression Metrics (RPM, MAP, Oil Pressure, Temperature, Power)**: Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), Mean Bias Error (MBE).
- **Nine-Class Fault Taxonomy (Module 13)**: Preserves class IDs $0..8$ (`NOMINAL`, `MISFIRE`, `DETONATION_KNOCK`, `EXHAUST_VALVE_LEAK`, `INTAKE_BOOST_LEAK`, `OIL_DEGRADATION`, `COOLING_FAULT`, `BEARING_WEAR`, `SENSOR_FAULT`). Computes Confusion Matrix, Per-Class F1, Macro Accuracy, Precision, Recall, and F1.
- **Anomaly Detection**: Detection Rate (TPR), False Positive Rate (FPR), False Negative Rate (FNR).
- **Remaining Useful Life (RUL)**: MAE (hours), RMSE (hours), Confidence Bounds Coverage Percentage.
- **Missing Data Handling**: Returns `status=NOT_AVAILABLE` or `unavailable_reasons` when reference labels are missing without fabricating metrics.

---

## 7. Validation Run & Report Reproducibility

- `ValidationRun`: Captures execution metadata (`validation_run_id`, `dataset_ids`, `config_version`, `timestamp`, `seed`, `metrics`, `status`).
- `ValidationReport`: Structured report aggregating dataset manifests, sample counts, audit results, metrics, warnings, and overall status (`PASS`, `FAIL`, `PARTIAL`, `NOT_AVAILABLE`).
- Identical inputs and random seeds yield 100% deterministic validation outputs.
